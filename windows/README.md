# Jev 对话助手（Windows）

**版本：v1.3.1** · [下载 Windows 版](https://github.com/QCJLchina/Jev-chat-assistant/releases/tag/v1.3.1)

Windows 桌面版使用 Vue 3 + TypeScript 界面和 pywebview 窗口，保留 Python 本地 OCR、Jev 判断、Windows 凭据管理器和本地安全检查。它可框选桌面上的任意聊天应用，不要求微信运行；不读取微信数据库，不注入微信进程，也不调用微信接口。

回复模型支持三种接口协议：`openai-chat`（`/chat/completions`）、`openai-responses`（`/responses`）和 `anthropic`（`/messages`）。Jev 会比较模型生成的三条候选回复，页面显示原始推荐概率，并在最高推荐项后标记红色“推荐”。不同服务可以保存为多套配置并切换。候选回复只能复制，不会自动填写或发送；交易相关对话仍会拒绝分析。

## v1.3.1 新功能

### 完整上下文

桌面 OCR 和粘贴文本默认分析全部消息，可主动选择最后 10／20／50 条。补充前文会先与当前消息合并，再按所选范围取消息。所选消息正文与背景说明合计最多 20,000 字符，超限时缩小范围或精简内容，不会静默截断。粘贴文本和补充前文本身也各有 20,000 字符的输入上限。界面统计显示总消息数、实际使用条数、字符数、所选消息上限和省略条数。交易内容检查覆盖完整输入，包括范围外的消息、前文、背景说明及 OCR 原文。

在“补充前文与背景”中粘贴更早的聊天，使用 `我：`／`对方：` 或 `me:`／`other:` 标注双方；无前缀行接续上一条消息，开头无前缀时按对方处理。背景说明独立作为上下文，不改变消息的发言方。补充只保留在内存，不保存为聊天历史；可手动清空，切换绑定目标窗口或退出应用时清除。同一窗口中切换联系人无法自动检测，切换会话前请自行清空补充。

### 窗口跟随

新安装默认使用窗口跟随；已有固定选区继续使用固定屏幕区域模式，重新框选也不会自动切换。要启用跟随，请先选择“跟随窗口”模式再重新框选；也可继续使用固定区域模式。跟随模式下，目标窗口移动时选区随之移动；跨不同 DPI 的显示器，仅在窗口几何信息保持一致时继续跟随。窗口尺寸变化超过 2 DIP 时需重新框选。目标窗口关闭或应用重启后，不会自动绑定到相似窗口：请检查并确认候选窗口后恢复绑定。

仅在点击分析时采集当前可见聊天，不持续在后台 OCR，不提供最小化或被遮挡窗口的后台采集。分析前请恢复目标窗口并确保聊天区域可见；确认候选窗口时核对实际会话。

## 环境

- Windows 10/11（x64）
- Python 3.12、Node.js 20+ 和 npm（源码运行/构建）
- Microsoft Edge WebView2 Runtime
- TypeSafe / Jev API Key
- 可选的回复模型 API Key

## 安装和启动

在仓库根目录打开 PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File .\windows\install.ps1
powershell -ExecutionPolicy Bypass -File .\windows\start.ps1
```

安装脚本会安装 Vue 依赖并构建前端，再安装 Python 依赖。首次使用时，在设置页保存 TypeSafe 控制台生成的 Jev API Key。新安装预置 DeepSeek、通义千问（百炼北京）、Kimi、智谱 GLM、豆包（火山方舟）、硅基流动、OpenAI、Anthropic Claude、Google Gemini、OpenRouter 和 Ollama 配置；编辑需要使用的供应商，填写其 API Key 后测试连接，再保存设置并选择为当前模型即可，无需手填 URL。已有用户的配置与主动清空的列表不会被覆盖。

“添加模型”同样可选供应商预设，自动填写地址、协议和推荐模型；选择“自定义”可手填协议与地址。API Key 填入后自动读取模型列表，读取失败保留推荐模型，也可手动输入。默认模型仅是推荐值，实际可用性取决于账号开通权限、余额及平台模型更新；百炼密钥需与北京地域匹配，其他地域请选择自定义地址。火山方舟预填模型尚需按控制台的模型/接入点 ID 确认。Ollama 需先在本机启动并安装模型，API Key 可留空，模型名称需与本地已安装模型一致。连接测试只发送固定短提示，不携带聊天内容；不会自动调用供应商进行收费测试。

接口地址可填基础地址（如 `https://host/v1`），也可填完整接口地址。程序会按所选协议推导请求端点：OpenAI Chat 使用 Bearer 认证，OpenAI Responses 使用 Bearer 认证，Anthropic 使用 `x-api-key` 和 `anthropic-version` 请求头。

回复模型密钥按配置分别保存到 Windows 凭据管理器；Jev 密钥也保存在凭据管理器。设置文件 `%APPDATA%\JevChatAssistant\settings.json` 只存非机密配置。旧版 DeepSeek 模型、密钥、关系说明、白名单和聊天框选坐标会在升级后继续可用；旧 DeepSeek API 密钥首次读取时迁移到对应模型凭据项。

## 使用

### 界面语言（v1.1.1）

在设置页的“界面语言”中选择跟随系统、简体中文、English、Français、Русский、日本語 或 한국어（韩文／朝鲜语）。语言独立保存并立即生效，不需要点击“保存设置”，也不会保存其他正在编辑的配置。写入失败会保留原语言。

首次使用默认跟随 Windows 当前用户的界面语言；英语、法语、俄语、日语、韩文和简体中文会匹配对应翻译，其他语言回退英语。韩文系统语言 ko-KR、ko-KP 均匹配 한국어。跟随系统会在启动或重新选择时重新检测。已有设置但没有语言字段的旧用户保持简体中文。切换后窗口标题、进度、错误、框选提示和 Jev 结果标签同步使用所选语言。

翻译资源内置在分发包中，离线可用。OCR 识别语言沿用现有实现；回复语言可指定或跟随界面语言。聊天原文、已有关系说明和模型名称不会自动翻译。

### 分析对话

1. 打开任意聊天应用并进入普通文字聊天。
2. 首次使用时点击“框选对话区域”，拖选屏幕上的聊天消息。新安装默认使用窗口跟随；已有固定选区用户要启用跟随，请先选择“跟随窗口”再重新框选。窗口跟随与重新框选条件见上文。
3. 选择要生成建议的回复模型，点击“分析当前选区”。
4. 查看 Jev 判断、候选推荐度与红色推荐项；点击复制后自行检查、修改和发送。

分析期间助手窗口会短暂隐藏，避免 OCR 将助手自身识别为聊天内容。已有桌面固定选区保留固定屏幕区域模式；更早的微信客户区选区升级时会清空，需重新框选。分析前请确保目标窗口和聊天区域可见。

## 文本分析与回复偏好

首页可切换“桌面选区”或“粘贴文本”。两种入口都会直接分析，不增加校对步骤。粘贴支持 `我：`、`对方：`、`me:`、`other:`；英文前缀不区分大小写，支持半角和全角冒号。无前缀行接续上一条消息，开头无前缀时按对方处理；空行忽略。粘贴输入最多 20,000 个字符。默认分析全部消息，可选最后 10／20／50 条，并按上文限制计算消息正文与背景说明的合计字符数。交易内容检查仍覆盖完整输入。文本模式不要求框选，也不使用窗口标题白名单。

设置页可保存回复长度（简短／详细）、风格（自然／正式／委婉／直接）和语言（跟随界面语言或六种指定语言）。旧配置继续使用简短、自然、中文。首页“本次回复偏好”可临时覆盖默认值，切换页面或开始新分析后仍保留，恢复默认或退出应用后清除；不会写入设置文件。详细回复默认使用 1,200 token 上限，简短回复使用 400；模型配置中明确填写的上限优先。语言和风格由模型按提示生成，实际效果取决于所选模型。

## 取消与重试

分析过程中可取消。取消会停止后续步骤并忽略旧请求返回的结果；已发送的网络请求可能继续运行到返回或超时，取消不保证撤销服务端请求或费用。

捕获／识别失败可重新识别；判断失败复用已识别文本；生成失败保留判断，仅重试生成；排序失败仍可复制未排序候选，也可只重试排序。取消后可以继续首个未完成阶段。重试沿用原任务的关系说明、模型与回复偏好；要应用新的设置，请重新分析。新分析会替换旧任务的内存缓存。聊天和阶段结果不写入本地历史文件。

## 构建分发程序

```powershell
powershell -ExecutionPolicy Bypass -File .\windows\build.ps1
```

产物位于 `dist\Jev对话助手\Jev对话助手.exe`。PyInstaller 会将 Vue 静态资源、OCR 模型和 Python 运行依赖一起打包，同时生成更新辅助程序 `update_helper.exe`（需与主程序同目录分发）。目标电脑需要 Microsoft Edge WebView2 Runtime；缺少时程序会显示提示。

脚本默认先执行 `npm ci` 和 `npm run build`。若前端已经构建完成（`windows/frontend/dist` 可用），加 `-SkipFrontendBuild` 跳过这两步，直接复用现有产物：

```powershell
powershell -ExecutionPolicy Bypass -File .\windows\build.ps1 -SkipFrontendBuild
```


## 应用内更新

应用支持在软件内自行拉取更新。启动后会延迟几秒静默检查 GitHub Releases；发现新版本时主页顶部出现提示横幅，也可以在设置页的"版本与更新"中手动检查。检查只向 `api.github.com` 查询最新版本号，不发送任何聊天内容。

确认更新后，应用在后台下载 Release 压缩包（可查看进度、可取消），随后进行 SHA256 校验（发布附件包含 `SHA256SUMS.txt` 时启用；否则降级为大小校验）并解压暂存。点击"重启并安装更新"后，主程序退出，辅助程序 `update_helper.exe` 用暂存内容原子替换安装目录并自动重启新版本；替换过程中任何一步失败都会回滚到旧版本，聊天数据与设置保存在 `%APPDATA%`，不受更新影响。

## 隐私边界

- OCR 在本机执行；点击分析后，识别出的聊天文本会发送给 TypeSafe Jev。启用回复模型时，对话和 Jev 判断也会发送给所选服务生成候选回复。
- 模型列表和连接测试只使用当前配置的接口地址、API Key 和模型信息，不会发送聊天内容。
- 界面桥接不会向前端返回已保存密钥；API Key 按配置 ID 存储在 Windows 凭据管理器，也不会写入日志或 `settings.json`。
- 不读取本地聊天数据库，不操作微信输入框，不自动发送。转账、红包、收款、支付等交易内容会拒绝分析。
- 当前面向可见的普通文字聊天；图片、语音和引用卡片不会被可靠还原。

## 常见问题

- **Jev 密钥无效**：填写 `console.typesafe.ai` 控制台生成的 API Key。
- **无法加载模型列表**：有些代理或服务不提供模型列表端点；可直接手动输入服务端支持的模型 ID。
- **连接测试失败**：核对协议、基础地址、API Key 和模型名称。Anthropic 配置应选择 `anthropic`；Responses 接口应选择 `openai-responses`。
- **无法启动桌面窗口**：安装或修复 Microsoft Edge WebView2 Runtime 后重试。
- **微信文字识别不完整**：重新框选聊天气泡区域，不要包含会话列表、标题或输入区。
